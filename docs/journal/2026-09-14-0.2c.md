# RainWatch development journal — Version 0.2c

Version 0.2c adds model-derived Total Cloud Cover for local interpretation without replacing or visually conflating the existing NOAA satellite layer.

## Provider and current-value semantics

- Provider: Open-Meteo Weather Forecast API.
- Endpoint: `https://api.open-meteo.com/v1/forecast`.
- Variable: `current=cloud_cover` only.
- Time format: Unix seconds in GMT, converted to browser-local display time.
- Model selection: Open-Meteo automatic Best Match, which selects suitable high-resolution models by coordinate and supports global use including Taiwan.
- Meaning: total cloud cover as an area fraction percentage from weather-model output, not directly observed satellite imagery.
- Timing: Open-Meteo documents current conditions as 15-minute model data. The response's `current.time` is the represented weather/model-valid time; RainWatch separately records when it fetched the response.

The provider is isolated in `src/services/cloudCover/OpenMeteoCloudCoverProvider.ts`. Latitude and longitude arrays are encoded as paired comma-separated lists. The current 5 × 5 and 7 × 7 strategies remain below the 50-coordinate batch cap, so a normal viewport uses one request. Larger future inputs would be split into batches of 50 rather than one request per point.

## Sampling and rendering

- Continental/large-scale views below zoom 5 use 5 × 5 cells (25 samples).
- Regional and local views use 7 × 7 cells (49 samples).
- The requested grid overscans the visible bounds by 12 percent so tiny pans do not expose immediate gaps.
- A completed pan must shift roughly 18 percent of the previous viewport, change scale by 25 percent, cross the grid-size breakpoint, or change zoom by 0.75 before a new request is made.
- Move and resize handling is debounced by 350 milliseconds.
- Up to six sampled viewport results are reused in memory for ten minutes. This is application memory only, not persistent service-worker weather caching.

MapLibre renders one GeoJSON polygon per sampled cell. Cell color and transparency grow with the reported percentage, while road, boundary, and place-label context stays above the overlay. The cells are intentionally not interpolated: the rendering communicates approximate model-grid coverage instead of inventing precision between samples.

RainWatch interpretation labels are:

- 0–19%: Mostly clear
- 20–49%: Partly cloudy
- 50–79%: Mostly cloudy
- 80–100%: Overcast

These are application labels, not official Open-Meteo meteorological thresholds.

## User experience

- Modes are Radar, Satellite, Cloud Cover, and Radar + Satellite.
- Satellite means observed NOAA GOES GeoColor imagery.
- Cloud Cover means model-derived total cloud fraction.
- Radar + Satellite preserves the former Both behavior and never adds Cloud Cover automatically.
- Cloud Cover has its own opacity control, provider attribution, model-valid time, checked time, freshness state, legend, and manual refresh.
- The compact summary uses the nearest sampled value to the user's location only when that location lies inside the sampled viewport. Otherwise it explicitly says that it describes the map center.
- The summary says the value is approximate and does not imply street-level resolution.

Cloud Cover uses a configurable 45-minute stale threshold for the represented current timestamp. This allows three missed 15-minute current intervals. Open-Meteo's underlying Best Match models have provider- and region-specific model-run updates, generally every one to six hours, so the app does not present the value as a second-by-second observation.

## Network and PWA behavior

Direct browser-origin testing returned `Access-Control-Allow-Origin: *`; no proxy is required. A three-location request successfully returned Austin, Taipei, and London values in one response.

Measured development-browser responses:

- 5 × 5 continental grid: one request, 25 usable values, approximately 8.1 KB JSON.
- 7 × 7 regional grid: one request, 49 usable values, approximately 16.0 KB JSON.
- A tiny pan did not change the fetch timestamp.
- A meaningful pan caused one replacement batched request.

The service worker explicitly routes `api.open-meteo.com` through `NetworkOnly`. The application shell remains precached, but Open-Meteo weather responses are never persistently served as current data by RainWatch.

## Known limitations

- Cloud Cover cells are intentionally approximate and not smoothly interpolated.
- A generic Best Match response does not name one fixed underlying model for every point.
- The local summary is limited by the selected model grid and RainWatch sampling density.
- There is no low/mid/high cloud selector, cloud animation, cloud-motion prediction, or radar/cloud synchronization.
- Real-device geolocation permission and iPhone Home Screen installation remain manual acceptance checks.
