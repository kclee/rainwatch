## Interactive MapLibre basemap

### What

Implemented the first version 0.1a product milestone: a responsive interactive map that supports mouse, keyboard, and touch-oriented MapLibre controls.

### How

- Added MapLibre GL JS 6.9.0 as a project-local dependency.
- Added `WeatherMap`, which owns the MapLibre instance and cleans it up when React unmounts the component.
- Added zoom controls, a scale indicator, and compact provider/data attribution.
- Added a `ResizeObserver` so the map canvas tracks its responsive container.
- Excluded MapLibre from Vite's development dependency optimizer because its worker module is loaded dynamically; this avoids a missing optimized-worker diagnostic during hot reload.
- Added a visible loading state and a graceful message for basemap loading errors.
- Isolated the style URL, default view, and zoom limits in `src/config/map.ts`.
- Selected the public OpenFreeMap Liberty style for development. Its attribution remains visible on the map.
- Added the optional `VITE_BASEMAP_STYLE_URL` override so the provider can be replaced without editing the UI component.
- Used a general continental United States fallback view; no personal location is hard-coded.

## Browser geolocation and location marker

### What

Added explicit, privacy-conscious browser geolocation. The map remains fully usable at its general fallback view until the user chooses **Use my location**.

### How

- Added `useGeolocation`, which owns permission requests and maps browser results into small application states.
- Added friendly handling for unsupported geolocation, permission denial, unavailable positions, timeouts, and unexpected errors.
- Requested cached, standard-accuracy positions with a ten-second timeout; high-accuracy GPS is not forced.
- Added a clear MapLibre marker when coordinates are available.
- Centered and zoomed the map near the returned position without a RainWatch backend or persistent storage.
- Changed the control to **Return to my location** after success; requesting again updates and recenters the marker.
- Kept the control at least 44 pixels tall for touch use.
- Kept precise coordinates in React memory only for the current page session. RainWatch has no backend or location persistence. As with ordinary interactive maps, the basemap provider receives tile requests for the area currently in view.
- Preserved the general continental United States fallback and normal map interaction when permission is denied or unavailable.

### Verification

- `npm run build` passed with the existing MapLibre bundle-size advisory.
- `npm run lint` passed with no reported issues.
- Browser inspection confirmed the location control, privacy note, full-height map, and absence of a marker before permission is requested.
- No application console errors or warnings were reported.
- At a 390 × 844 viewport, the location button remained 44 pixels tall, the map remained usable, and the document had no horizontal overflow.
- The test did not click the location button or grant location permission, so no real location was accessed or transmitted. Permission-granted behavior requires user verification in their normal browser.

## First RainViewer radar frame

### What

Added the first real radar overlay while deliberately limiting the UI to one frame. RainWatch fetches the available historical frames and displays the newest one above the basemap.

### How

- Added the small `RadarProvider` interface and provider-neutral `RadarFrame` type.
- Added `RainViewerRadarProvider`, which owns the metadata endpoint, response validation, historical-frame filtering, tile URL construction, and attribution.
- Used only `radar.past`; the app does not read or assume the existence of future/nowcast frames.
- Kept frames within approximately two hours of the newest available historical frame.
- Used RainViewer's 256-pixel raster tiles, Universal Blue color scheme 2, smoothing, and separate snow colors.
- Declared RainViewer's documented maximum native tile zoom of 7 and allowed MapLibre to overzoom the raster at closer map levels.
- Inserted the radar layer below the basemap's first symbol layer so labels remain readable.
- Set a temporary fixed radar opacity of 68 percent pending the later opacity control.
- Added a ten-second metadata timeout, invalid-response handling, an empty-frame state, and a radar-tile failure message that leaves the basemap usable.
- Displayed the selected radar frame in the user's local time zone.

### Verification

- RainViewer's official metadata endpoint returned API version 2.0 with 13 past frames at ten-minute intervals and zero nowcast frames during the check.
- RainViewer's documented tile host and historical frame paths were used to construct the current raster template.
- `npm run build` passed with the existing MapLibre bundle-size advisory.
- `npm run lint` passed with no reported issues.
- Live browser inspection confirmed the newest radar frame, local timestamp, RainViewer attribution, basemap labels, location control, and absence of application console errors.
- At 390 × 844, the radar status remained compact, the location control stayed 44 pixels tall, and the document had no horizontal overflow.
- No location permission was requested during radar verification.

## Documentation convention

- `progress.html` provides a concise visual status dashboard.
- `docs/journal/YYYY-MM-DD.md` records implementation methods, verification evidence, affected files, and commit subjects.

Documentation should be updated with each meaningful milestone rather than every tiny edit.
