# RainWatch development journal — Version 0.2d

Version 0.2d adds one compact current surface-wind readout without introducing a wind map, particle animation, cloud-motion claim, or additional provider.

## Data and semantics

RainWatch calls the Open-Meteo Forecast API at `/v1/forecast` with:

- `current=wind_speed_10m,wind_direction_10m,wind_gusts_10m`
- `wind_speed_unit=mph`
- Unix timestamps and GMT
- Open-Meteo's automatic **Best Match** model selection

The 10 m level is standard near-surface wind. Open-Meteo current conditions use 15-minute model data where available. Gusts are distinct from the sustained/current speed and may be omitted when the provider does not return them.

Meteorological direction means where wind comes **from**. RainWatch converts the source degree into a 16-point compass label, then adds 180 degrees for the movement direction. Therefore `270°` displays as **W → E**, and the arrow points east. This convention is centralized and tested so the visual arrow cannot silently reverse the meaning.

## Location behavior

The map reports its viewport after initial load and completed movement. If the browser's user location lies inside that viewport, the card says **Wind near you** and requests that coordinate. Otherwise it says **Wind at map center** and requests the current center only. It never implies that one value represents the entire map.

A completed movement must shift the wind target by at least 25 km before it causes a replacement request. Results are cached in memory for ten minutes by rounded location and source. There is no background polling and no request on every small map movement.

The Wind card has its own refresh action. Existing Radar, Satellite, Cloud Cover, and Smooth Cloud refresh controls retain their prior meanings.

## Freshness and failures

The card separates the model/current-condition timestamp from RainWatch's checked time. Wind is marked stale after **45 minutes**, independently configured as three expected 15-minute current-condition intervals.

Requests time out after ten seconds. HTTP errors including 429, network failures, incomplete values, and offline state produce a compact unavailable message. If an older reading exists, it remains visible with a last-available warning. These states do not affect the map or any other weather layer.

Open-Meteo API traffic remains covered by the existing Workbox `NetworkOnly` rule, so the service worker never presents a cached wind response as current.

## User interface

The map contains one compact card showing:

- whether the reading applies near the user or at map center
- source direction and movement direction
- a movement arrow
- current speed in mph
- gust speed when available
- model time and checked time
- a subtle note that surface wind can differ from cloud motion aloft

No field overlay or additional map arrows were added.

## Known limitations

- The reading is model-derived 10 m surface wind, not a weather-station observation.
- Terrain, buildings, and local exposure can make actual wind differ from the selected model grid point.
- Surface wind does not establish cloud or rain motion aloft and is not used for ETA.
- There is no wind field, particle animation, streamline, upper-air wind, or history in this milestone.
