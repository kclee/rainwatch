# RainWatch development journal — Version 0.2b

Version 0.2b adds one latest cloud/satellite view without changing RainWatch's existing radar architecture or introducing cloud animation.

## NOAA service and integration

- Provider: NOAA/NESDIS merged GOES-East and GOES-West GeoColor.
- Service: [`Most_Recent_MERGEDGC`](https://satellitemaps.nesdis.noaa.gov/arcgis/rest/services/Most_Recent_MERGEDGC/ImageServer).
- Metadata: the provider queries the service's single latest raster record and reads its `end_time` timestamp.
- Rendering: MapLibre image source using ArcGIS ImageServer `exportImage` in EPSG:3857 Web Mercator.
- CORS: direct metadata and image requests returned HTTP 200 and allowed the `https://kclee.github.io` origin, so no backend proxy was needed.
- Attribution: `Satellite © NOAA/NESDIS` remains visible whenever the cloud layer is active.

The browser requests only the visible map bounds. Output is capped at 1600 × 1200 pixels and 1.5× device pixel density. Image requests occur after a completed pan/zoom, a meaningful resize, a metadata refresh, or initial activation—not on React renders or minor pointer movement. Resize and move updates are debounced by 250 milliseconds.

## User experience

- **Radar** preserves the complete 0.2a radar timeline, animation, legend, refresh, and opacity behavior. Cloud imagery is removed and does not download.
- **Cloud** displays the latest NOAA GeoColor image, its relative and exact local timestamp, and a cloud-opacity control. Radar is hidden.
- **Both** orders layers as basemap, satellite, radar, map labels, location marker, and UI. Radar defaults to 70% opacity and cloud imagery to 45%.
- Radar and cloud timestamps are visibly separate and are not presented as synchronized observations.
- A combined refresh action refreshes whichever providers are visible while retaining an existing radar selection when the frame still exists.

GeoColor is not a cloud-cover percentage product. It combines visible-color information during daylight with infrared/multispectral presentation at night, so nighttime appearance differs from daytime imagery.

## Freshness and failures

The latest service describes a ten-minute time extent and live records advanced on an approximately ten-minute cadence during implementation. RainWatch uses an independent configurable cloud stale threshold of **35 minutes**, allowing for slower scan modes and publication delay.

Cloud metadata, timestamp, image, CORS, timeout, empty-result, and stale states produce compact non-blocking notices. In Both mode, one failed provider does not remove the other working layer or blank the basemap.

During browser testing, an invalid `orderByFields` query revealed that the service advertises no sortable fields. Because `Most_Recent_MERGEDGC` contains only the latest image, sorting was removed. A simpler one-record query is both correct and more reliable.

## PWA behavior

The application shell remains precached. The NOAA `satellitemaps.nesdis.noaa.gov` host now has an explicit Workbox `NetworkOnly` route alongside RainViewer and OpenFreeMap, preventing old satellite imagery from being presented as current by RainWatch's service worker.

## Known limitations

- Version 0.2b shows one latest cloud image; it has no cloud history or animation.
- Radar and satellite frames are not synchronized.
- Satellite appearance changes between daylight and nighttime rendering.
- NOAA availability and latency determine whether current imagery can be shown.
- The service's latitude extent stops near 76° north and south; polar and antimeridian views are outside this milestone's focus.
- Every live map and weather layer still requires network access.
