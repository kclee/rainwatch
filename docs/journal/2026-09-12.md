# RainWatch development journal — 2026-09-12

This entry records the RainWatch 0.2a radar-clarity milestone. Version 0.1 remains the functional foundation; this milestone improves how users interpret radar intensity, observation time, metadata freshness, and provider failures.

## Radar clarity and trust

### What changed

- Added a compact radar-intensity legend matched to RainViewer color scheme 2, **Universal Blue**.
- Used representative documented palette colors for light, moderate, heavy, and intense reflectivity, with an explicit note that the guide is not an exact rainfall-rate conversion.
- Changed timeline presentation to relative observation age with an absolute local timestamp underneath. The newest frame is labeled `Latest`, not `Now`.
- Added a separate metadata-refresh indicator and a manual **Refresh radar** action.
- Preserved the selected historical frame when refreshed metadata still contains it.
- Kept already-loaded frames during a failed refresh and clearly identifies them as the last available frames.
- Removed the radar layer after a successful metadata response contains no frames, while keeping the basemap usable.
- Added a delayed-data warning when the newest observation is at least 30 minutes old. At the currently observed ten-minute cadence, that represents roughly three missed updates.
- Centralized palette, tile-option, clock, playback, and freshness-threshold settings rather than scattering provider assumptions through UI code.

### Provider evidence

- RainViewer's [Weather Maps API documentation](https://www.rainviewer.com/api/weather-maps-api.html) defines the historical frame metadata and tile URL format used by the provider.
- RainViewer's [color-scheme documentation](https://www.rainviewer.com/api/color-schemes.html) identifies scheme 2 as Universal Blue and publishes its reflectivity color table.
- On 2026-09-12, the live metadata response contained 13 historical frames at approximately ten-minute intervals.
