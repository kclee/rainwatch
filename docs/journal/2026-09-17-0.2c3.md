# RainWatch development journal — Version 0.2c3

Version 0.2c3 moves the validated Open-Meteo Weather Map Layer experiment into the normal RainWatch interface as a fifth, explicitly experimental mode. It is a usability trial, not a migration: the existing sampled **Cloud Cover** mode remains available and unchanged.

## Integration

- **Cloud Cover** continues to use the Open-Meteo Forecast API and RainWatch's 5 × 5 / 7 × 7 sampled cells.
- **Smooth Cloud · Lab** uses `@openmeteo/weather-map-layer` **0.1.1**, MapLibre's custom `om://` protocol, NOAA **HRRR CONUS**, the `cloud_cover` variable, linear interpolation, and color blending.
- The map-layer package is dynamically imported only after Smooth Cloud is selected. Its code and WebAssembly reader are excluded from the PWA app-shell precache, so opening RainWatch normally does not download the experiment.
- Open-Meteo metadata and `.om` range requests are network-only. There is no background polling; refresh remounts the current layer on demand, while the library can reuse already-read blocks and cancel obsolete tile work.
- The official HRRR domain footprint determines whether the map center is supported. Outside it, RainWatch removes the weather raster and shows a clear continental-U.S. coverage notice while keeping the basemap and every other mode usable.

## User experience

The mode selector now contains Radar, Satellite, Cloud Cover, Smooth Cloud · Lab, and Radar + Satellite. Smooth Cloud has its own legend, timestamp, refresh action, attribution, failure state, and opacity control. The default opacity is **78%**, which kept the field readable without hiding roads and place labels during browser testing.

The timestamp is labeled **HRRR forecast · Next hour** and shows the valid hour used by the `current_time_1H` source. Its load time is tracked separately. It is not presented as the sampled grid's model time, NOAA satellite time, or radar observation age.

## Attribution and licensing

The map displays the library-provided **Weather data by Open-Meteo.com** attribution and a persistent RainWatch Open-Meteo link while Smooth Cloud is active.

The installed Weather Map Layer package currently declares **GPL-2.0** and remains pre-1.0 at version 0.1.1. Open-Meteo data is subject to its attribution requirements. This experimental integration does not settle whether that library license is appropriate for a long-term production dependency; a licensing decision is still required before treating Smooth Cloud as a permanent replacement.

## Comparison notes

| Area | Sampled Cloud Cover | Smooth Cloud · Lab |
| --- | --- | --- |
| Visual clarity | Deliberately visible cells with approximate categories | Continuous field with much clearer cloud boundaries |
| Local usefulness | 7 × 7 viewport sampling; honest but coarse | Smooth at local zoom, though still forecast-model output rather than street-level observation |
| Regional usefulness | Checkerboard becomes prominent | Strongest improvement; coherent systems are easy to follow |
| Network transfer | About 8 KiB for 5 × 5 and 16 KiB for 7 × 7 in prior measurements | About 264 KiB regionally and 1.0 MiB for a fresh whole-USA view in the research spike |
| Loading latency | Usually one compact API response | Progressive; prior fresh measurements were about 1.6 seconds regionally and 2.4 seconds nationally |
| Interaction | One debounced replacement request after a meaningful move | Partial 64 KiB ranges, block reuse, and progressive tiles; more computation and data |

These observations do not choose a winner. The two modes remain side by side so usefulness and device cost can be judged during ordinary use.

## PWA behavior

Smooth Cloud is part of the main application state rather than a separate navigation route, so an old service worker cannot incorrectly route a new experiment page. The app shell, manifest, and normal static assets remain precached. The experimental engine, Open-Meteo metadata, and live `.om` data remain network-dependent and are not cached for offline weather use.

## Known limitations

- Smooth Cloud covers the NOAA HRRR CONUS footprint, not the world. Sampled Cloud Cover remains the global alternative.
- The layer is forecast-model total cloud fraction, not observed cloud imagery.
- The model/run display is a relevant next-hour valid timestamp; the current library source does not expose a separate run-cycle label to RainWatch.
- First use is materially heavier than sampled Cloud Cover and must download the lazy engine plus progressive weather ranges.
- Live weather still requires network access; range, metadata, render, or library failures fall back to a message and usable basemap.
- Package maturity and GPL-2.0 compatibility remain unresolved product decisions.
- Cloud animation, global model routing, wind, and radar/cloud synchronization remain out of scope.
