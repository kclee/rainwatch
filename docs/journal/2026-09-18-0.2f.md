# RainWatch development journal — Version 0.2f

Version 0.2f gives Radar + Satellite one historical reference timeline and pairs existing observations by timestamp. It does not add motion analysis, ETA, extrapolation, forecasts, or a third playhead.

## Reference timeline and live cadence

Satellite is the reference because its existing archive spans approximately three hours and already has a visible historical selector. Combined mode reuses that exact Previous/Next, slider, Play/Pause, timestamp, frame count, and Satellite-opacity state. Radar updates automatically and retains its independent opacity.

Live provider metadata on 2026-09-18 contained:

- 13 RainViewer records at ten-minute intervals, on `:00/:10/:20/...`
- NOAA archive records at ten-minute intervals, ending on `:09/:19/:29/...`
- one-minute differences for normal overlapping pairs

The configurable maximum acceptable difference is **15 minutes**. This permits a normal offset or one missed publication but treats a two-interval gap as poor. Match quality is concise:

- **Close match:** 0–5 minutes
- **Moderate difference:** over 5 through 15 minutes
- **Large difference:** over 15 minutes

These labels describe timestamp separation only.

## Matching algorithm

`src/utils/frameMatching.ts` accepts a target timestamp, provider-neutral candidates, and a timestamp accessor. It ignores invalid timestamps, compares absolute differences, and returns the closest frame plus the difference. An exact match wins naturally. Equal-distance ties choose the **earlier** observation so results are deterministic regardless of input order.

If a Satellite target lies outside the available Radar window and the closest Radar record is more than 15 minutes away, RainWatch removes the Radar layer, keeps Satellite visible, and says no suitable Radar observation exists. A large gap inside the comparison range may remain visible with an explicit Large difference warning. No frame is fabricated.

If the Satellite archive is unavailable but the latest NOAA image remains available, combined mode can still pair that latest timestamp with Radar while explaining that history is unavailable. Radar metadata failure keeps Satellite visible. Individual MapLibre source failures remain isolated to their layer.

## Playback and UI

Radar + Satellite contains no Radar-history slider. The Satellite timeline is the only playhead:

1. select or advance Satellite
2. find the closest Radar frame
3. update only that Radar source
4. show both exact local timestamps
5. show the absolute delta and quality label

Standalone Radar keeps its 800 ms timeline and controls. Standalone Satellite keeps its 1.5 second timeline and controls. Switching historical pairs does not reset either opacity value. Layer order remains basemap, Satellite, Radar, labels, then marker/UI.

## Bandwidth measurement

Measurements used the default whole-USA extent. Each matched Radar frame required 10 visible 256-pixel tiles.

| Interaction | Additional Radar transfer beyond Satellite |
| --- | ---: |
| Enter combined mode on the current pair | 97,188 bytes (about 95 KiB) |
| Three additional matched frames | 294,550 bytes (about 288 KiB) |
| Average measured matched frame | 98,112 bytes (about 96 KiB) |
| Full 18-frame Satellite loop: 12 matched Radar frames | 1,177,347 bytes (about 1.12 MiB) |
| Six older, non-overlapping Satellite frames | 0 Radar bytes |

The full loop made 120 unique Radar tile URLs. Revisiting an already loaded matched frame reused the identical URLs and completed each tile in roughly 3–7 ms in the browser. Cross-origin Resource Timing intentionally hid transferred byte counts, so no unsupported zero-byte claim is made. RainViewer responses advertised a two-day browser cache lifetime. Radar remains network-only in Workbox; the existing bounded Satellite CacheFirst policy is unchanged.

## Verification

- Live overlapping pairs displayed exact `12:09 AM` Satellite and `12:10 AM` Radar times with `Δ 1 min · Close match`.
- Previous changed both frame IDs; Play advanced the single Satellite timeline and restored the next matched pair; Pause stopped it.
- The combined view had no Radar-history slider or second playhead.
- Satellite and Radar opacity stayed at 45 and 70 percent across frame changes and playback.
- Home selected a three-hour-old Satellite frame outside Radar history, removed Radar, and displayed the no-match notice plus Radar unavailable state.
- Standalone Radar retained Previous, Play/Pause, and its independent slider.
- Standalone Satellite retained its existing historical controls.
- At 390 × 844, both timestamps, match status, both opacity controls, and 44-pixel playback buttons remained reachable with no horizontal overflow.
- Browser verification produced no application console warnings or errors.
- Automated tests cover exact, closest-earlier, closest-later, equal-distance tie, empty, single-frame, and all four quality outcomes.
- `npm test`: **30 of 30 passed**.
- `npm run lint`: passed.
- `npm run build`: passed and preserved the existing PWA runtime strategies.

## Scope intentionally excluded

- motion vectors or optical flow
- radar/cloud motion prediction
- rain, cloud, or clearing ETA
- forecast extrapolation
- new providers or geographies
- backend, database, accounts, or native application
